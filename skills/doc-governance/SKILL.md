# 文档治理

> 本技能由 **dsh-doc-kit** 随包提供：源头在插件包 `skills/doc-governance/SKILL.md`。
> 直接改技能库副本不会生效——改仓库那份，重装或重载后自动覆写。

事实的唯一真源＝文档；**自动注入位置只放索引**。本技能管三件事：该写进哪里、写前查什么、多久体检一次。

## 分层与归属（每支都要用）

| 层 | 位置 | 放什么 | 注入范围 |
|---|---|---|---|
| 全局 | `$DSH_HOME/AGENTS.md` | 只放指针 + 守门规则 | 所有会话 |
| 工作区 | 工作区根的 `AGENTS.md` | 真源表（位置 + 何时读） | 工作区内、且未进自带 `.git` 的项目 |
| 项目 | `<项目>/AGENTS.md` | 项目硬约定 | 该项目目录内 |
| 按需 | `docs/*.md`、域或项目的 `CONTEXT.md`、handoff 文档 | 全部事实与细节 | **不注入** |

各层的具体路径由你的工作区布局决定（`doc_lint` 的工作区根默认取当前会话 cwd）。

**归属判定顺序**：项目内 → 项目文档；域通用 → 域文档；跨项目 → 工作区 `docs/`。
要独立成文前先问「第二个消费者是谁」：只有一个项目用，就写进那个项目。

## 写文档（步骤）

1. **先查有没有写过**：`grep` 拟写主题的关键词。命中就**就地改**，不新建。完成判据：要么改了那处，要么确认全仓无命中。
2. **定归属**：按上面的顺序选出**唯一**归属文档。完成判据：说得出「为什么是它、而不是上一层或下一层」。
3. **新文档补一行边界**：`> 本文件负责 X；不属于本文件的 Y 见 Z`。
4. **改注入层要停下**：任何往全局 / 工作区 / 项目 `AGENTS.md` 加内容的动作，**先问用户**。完成判据：拿到明确同意，否则不加。

## 整理 / 去重（步骤）

1. 先出清单，**等用户确认**再动手。
2. 归档优先于删除；只有内容完全等价才删。
3. 相似度只作**排序参考**，必须逐条比对——措辞差异会把真重复压到 0.4~0.5。
4. 分小批（≤20 条）；**先落载体、再封存源**，顺序不能反。

## 收尾体检（调 `doc_lint`）

跑 dsh-doc-kit 注册的只读工具 `doc_lint`，它查四项：

- `[FAIL] quota`：注入层超出自律配额（默认全局 ≤ 2 KB、工作区 ≤ 4 KB）——有人在往注入层塞东西。
- `[FAIL] banned`：注入层出现「曾用 / 已废弃 / 已被推翻 / 别再试」这类决策史。
- `[WARN] index`：索引点名的文档不存在。（描述**他人惯例**的单元格会被自动跳过，不算命中。）
- `[WARN] git`：治理文件未进 git —— 没有 diff 历史，漂移无从发现。

硬失败的必须处理；提示项逐条判断。

## 对外发布前（上传仓库前过一遍）

公开仓库是**永久痕迹**（会被镜像/索引，删除不等于消失），所以宁可多花一分钟：

- **本机专属条目**：个人笔记文件名（HANDOFF / LOCAL_PATCHES 之类）、`.scratch` 类路径——**一个都不进**。注意 ignore 文件**本身是项目配置**（该进仓库），要剔的是里面只对你那台机器成立的**条目**；那些放 `.git/info/exclude`（本地、永不提交）。
- 敏感扫描：凭据 / 本机绝对路径 / **内部仓名与项目名**（你工作区里出现的目录名、夹具里的例子也算——只列几个具体名字去 grep，一定漏）。
- **默认不带开发史**：对外仓＝干净单提交快照，本地开发史留在开发仓（能不带就不带）。要带史是例外——先报备「为什么必须」。
- 快照仓的更新＝就地 `--force-with-lease` 覆盖，旧快照在本地留回退分支；一旦有外部依赖者（被 fork/clone、被引用）就停止改写——改推新提交或另建仓。
- 不论带不带历史都不进：中间产物 / 一次性探针 / 本机专属条目（个人笔记名、`.scratch` 类路径）。
- 报备给用户时把**建议项单独标出**，不要和必需项平铺在一张清单里。

## 坑（平台行为，都实测过）

- 自带 `.git` 的项目**与工作区层断链**：项目根＝它自己，工作区根的 `AGENTS.md` 不会被注入 → 所以全局层必须带那条指针。
- 嵌套层只在成功的 `read` / `write` / `edit` 触达更深目录时加载；**`bash cd` / `cat` 不触发**。
- `CONTEXT.md` **不自动注入**——候选名只有 `AGENTS.md` / `CLAUDE.md`。
- 第三方仓（克隆来的参考目录）自带的 `AGENTS.md` 会跨信任边界被当指令注入（平台已知限制）→ 那里不建长会话。
- 「更具体者优先」是平台强制的，层级冲突不用自己定规则。
